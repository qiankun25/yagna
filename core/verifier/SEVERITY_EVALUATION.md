# 严重程度评判系统说明

## 概述

严重程度评判系统是验证器的核心改进，通过多维度评分自动评估违规行为的严重程度，并据此进行分级惩罚。

## 评判维度

### 1. 共谋检测（40%权重）

**目的**：识别多个Provider是否串通提交相同错误结果

**评判标准**：
- 共谋比例 ≥ 30% → 1.0分（非常严重）
- 共谋比例 20-30% → 0.8分（严重）
- 共谋比例 < 20% 但 ≥ 2个节点 → 0.6分（中等）
- 单个节点违规 → 0.2分（轻微）

**示例**：
```
5个Provider中，3个提交相同错误结果
共谋比例 = 3/5 = 60% > 30%
得分 = 1.0 × 40% = 0.4
```

### 2. 违规频率（25%权重）

**目的**：检测短时间内重复违规行为

**评判标准**：
- 1小时内重复违规5次以上 → 1.0分（非常严重）
- 1小时内重复违规3-4次 → 0.8分（严重）
- 1小时内重复违规2次 → 0.6分（中等）
- 间隔时间较长或首次违规 → 0.2-0.3分（轻微）

**时间窗口**：1小时（3600秒）

### 3. 结果一致性模式（20%权重）

**目的**：分析错误结果的模式特征

**评判标准**：
- 多个节点提交完全相同的错误结果 → 0.8分（共谋模式）
- 单个节点提交错误结果 → 0.3分（随机错误）

### 4. 历史记录（15%权重）

**目的**：基于Provider的历史违规记录

**评判标准**：
- 历史违规10次以上 → 1.0分（惯犯）
- 历史违规5-9次 → 0.8分（严重）
- 历史违规2-4次 → 0.5分（中等）
- 历史违规1次 → 0.3分（轻微）
- 首次违规 → 0.2分（轻微）

## 综合评分

**计算公式**：
```
总分 = 共谋检测得分 × 40% + 违规频率得分 × 25% + 
       结果模式得分 × 20% + 历史记录得分 × 15%
```

**评判结果**：
- **总分 ≥ 0.7** → **Severe（严重）**
- **总分 ≥ 0.4** → **Moderate（中等）**
- **总分 < 0.4** → **Minor（轻微）**

## 惩罚分级

根据严重程度，惩罚比例不同：

| 严重程度 | 扣除比例 | 说明 |
|---------|---------|------|
| Minor | 0.5% | 可能是硬件故障或偶然错误 |
| Moderate | 1% | 重复错误或明显异常 |
| Severe | 5% | 共谋攻击或系统性恶意行为 |

## 实际案例

### 案例1：共谋攻击

**场景**：
- 5个Provider执行任务
- 3个Provider共谋，提交相同错误结果
- 2个Provider提交正确结果

**评判过程**：
```
共谋检测：3/5 = 60% > 30% → 1.0分（40%权重）→ 0.4
违规频率：首次违规 → 0.2分（25%权重）→ 0.05
结果模式：共谋模式 → 0.8分（20%权重）→ 0.16
历史记录：首次违规 → 0.2分（15%权重）→ 0.03

总分 = 0.4 + 0.05 + 0.16 + 0.03 = 0.64
```

**结果**：Moderate（中等）→ 扣除1%质押

**注意**：如果共谋比例更高（如4/5），总分可能达到0.7以上，判定为Severe。

### 案例2：随机错误

**场景**：
- 5个Provider执行任务
- 1个Provider提交错误结果（可能是硬件故障）
- 4个Provider提交正确结果

**评判过程**：
```
共谋检测：单个节点 → 0.2分（40%权重）→ 0.08
违规频率：首次违规 → 0.2分（25%权重）→ 0.05
结果模式：随机错误 → 0.3分（20%权重）→ 0.06
历史记录：首次违规 → 0.2分（15%权重）→ 0.03

总分 = 0.08 + 0.05 + 0.06 + 0.03 = 0.22
```

**结果**：Minor（轻微）→ 扣除0.5%质押

### 案例3：重复违规

**场景**：
- Provider在1小时内连续违规3次
- 每次都是单个节点错误（无共谋）

**评判过程**：
```
共谋检测：单个节点 → 0.2分（40%权重）→ 0.08
违规频率：1小时内3次违规 → 0.8分（25%权重）→ 0.2
结果模式：随机错误 → 0.3分（20%权重）→ 0.06
历史记录：3次违规 → 0.5分（15%权重）→ 0.075

总分 = 0.08 + 0.2 + 0.06 + 0.075 = 0.415
```

**结果**：Moderate（中等）→ 扣除1%质押

## 惩罚计算示例

### 按比例扣除模式

```rust
// Provider A: 质押1000代币
// 首次违规（中等严重程度）
penalty = 1000 × 1% = 10代币

// 二次违规（惩罚递增1.5倍）
penalty = 1000 × 1.5% = 15代币

// 三次违规（惩罚继续递增）
penalty = 1000 × 2.25% = 22.5代币

// Provider B: 质押100代币
// 首次违规（中等严重程度）
penalty = max(100 × 1%, 1.0) = 1代币（最小惩罚保护）
```

### 严重程度影响

```rust
// 同一Provider，不同严重程度
// 质押1000代币

// 轻微违规
penalty = 1000 × 0.5% = 5代币

// 中等违规
penalty = 1000 × 1% = 10代币

// 严重违规（共谋攻击）
penalty = 1000 × 5% = 50代币
```

## 优势

1. **自动识别**：无需人工判断，系统自动评估严重程度
2. **客观公正**：基于可量化的指标，避免主观偏见
3. **公平合理**：按比例扣除，大额质押者损失更大
4. **威慑力强**：共谋攻击惩罚更重，有效防止系统性攻击
5. **保护善意**：区分硬件故障和恶意行为，避免误伤

## 配置参数

可以通过 `SlashingConfig` 调整评判参数：

```rust
let config = SlashingConfig {
    penalty_mode: PenaltyMode::Proportional,
    base_slash_ratio: 0.01,              // 基础扣除比例1%
    repeat_offense_multiplier: 1.5,      // 重复违规递增倍数
    max_slash_ratio: 0.10,               // 最大扣除比例10%
    min_penalty_amount: 1.0,             // 最小惩罚1代币
    max_penalty_amount: Some(100.0),      // 最大惩罚100代币
    severity_ratios: {
        let mut map = HashMap::new();
        map.insert(OffenseSeverity::Minor, 0.005);    // 0.5%
        map.insert(OffenseSeverity::Moderate, 0.01);  // 1%
        map.insert(OffenseSeverity::Severe, 0.05);     // 5%
        map
    },
};
```

## 使用建议

1. **生产环境**：使用 `PenaltyMode::Proportional`（按比例扣除）
2. **测试环境**：可以使用 `PenaltyMode::FixedAmount`（固定金额）
3. **调整参数**：根据实际网络情况调整严重程度比例和递增倍数
4. **监控分析**：定期分析违规历史，优化评判参数
